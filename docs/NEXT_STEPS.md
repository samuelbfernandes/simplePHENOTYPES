### A real bug this surfaced, worth remembering

The first implementation reconstructed progeny phase from the `-1/0/1` dosage. That
cannot work: a dosage cannot express the phase of a heterozygote, so an F1 — which is
heterozygous at every segregating site — came back with one all-allele-1 strand and one
all-allele-2 strand. Every subsequent generation then recombined haplotypes the founders
never had, and DH progeny came out carrying the **ancestry mask** rather than founder
alleles (constant runs instead of segmentwise parental copies).

It was invisible to the isqg parity suite, which only ever compares first-generation
genotypes, and invisible to F2/DH segregation ratios, which still looked like a textbook
1:2:1 and 1:1. It showed up only when checking recombination against Haldane and finding
r = 0.99 at 0.9 cM — impossible, since r cannot exceed 0.5.

Fix: `mate_haplotypes()` / `mate_haplotypes_core()` return the phased strands, and the R
layer stores those. Guarded by a Rust test (alternating-allele founders, so a mask and a
real haplotype cannot be confused) and an R regression test.

**Lesson for the remaining work: segregation ratios are a weak check.** They passed
throughout. Only a linkage-based check caught it.

### Also worth knowing

PleioArch's `cor` is unbiased but *noisy per run*. Realized genetic correlation averaged
over 12 seeds tracks the target closely (0.010 / 0.233 / 0.489 / 0.871 for targets
0.0 / 0.3 / 0.6 / 0.9), but the across-seed standard deviation is ~0.4 at `n_qtn = 10`,
falling to ~0.16 at `n_qtn = 200`. DECISION-010 and SPEC's "realizes it exactly in
expectation" is literally true but reads as a stronger guarantee than a single run gives.
The vignette now says so explicitly.

## Done 2026-09-07 (afternoon) — isqg Rust port, exact-parity gated

**DECISION-012** recorded: meiosis randomness is drawn in R in isqg's exact order, the
Rust core is a pure function of pre-drawn randomness, and **exact bit-parity** is the
gate. This resolves a contradiction between ARCHITECTURE §6 (which asked only for
statistical equivalence) and DECISION-006 (which forbids RNG in Rust); §6 has been
reworded to match.

The key finding that made it possible: isqg draws from R's own RNG, so replicating its
draw order in R (`rpois` → `runif` → `rbinom` per chromosome, the Bernoulli drawn even
when there are no crossovers) reproduces its output byte-for-byte. Verified against
`spc$gamete()`, `selfcross()` and `dh()` before any Rust was written.

- `inst/extdata/isqg_v1_outputs/` — capture script + 6 fixtures (8.7 KB). Each stores
  the drawn `counts`/`chiasmata`/`flips` **alongside** isqg's output, so a parity failure
  is unambiguously a Rust bug rather than an R draw-order bug. The script refuses to save
  a fixture it cannot reproduce from its own recorded draws.
- `src/rust/src/genome.rs` + `meiosis.rs` — bit-packed `Bits`, `GenomeLayout`,
  `EventStream` (ragged decoding via prefix sum), `chromosome_mask`, `recombine`, and one
  `mate_core` covering cross/selfcross/dh. No new crate dependencies; no RNG. 28 Rust
  unit tests, clippy `-D warnings` and `cargo fmt` clean.
- `tests/testthat/test-isqg-parity.R` — 22 assertions, all exact.
- **Mutation-tested the gate**: injecting the off-by-one in the breakpoint index, and
  separately skipping the Bernoulli when a chromosome has no crossovers, each fail 5
  assertions. The gate is not vacuous.
- Fixed along the way: `rextendr::document()` silently dropped
  `useDynLib(simplePHENOTYPES, .registration = TRUE)` from NAMESPACE, because roxygen2
  >= 7.3 deprecates the `@docType package` block rextendr emits. Without it the compiled
  code never loads. The directive now lives in a hand-maintained
  `R/simplePHENOTYPES-package.R` using `"_PACKAGE"`, so it survives regeneration.
  Also cleared a pre-existing clippy failure in `numeric.rs` (`into_iter` on a ref).

Suite: **184 pass / 0 skip**. `rcmdcheck`: **0 errors / 0 warnings / 0 notes**.
